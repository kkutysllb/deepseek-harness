# @qilin/account-core

[English](README.md) | 中文

面向多用户表面的账户域核心:用户与会话实体、持久化 SQLite 存储与 scrypt 密码哈希。存储层持有两张表——users 承载唯一 email、封闭的 admin/user 角色集、OAuth 联结列、补全标记与单调递增的会话版本;sessions 引用其属主用户并记录签发时该账户的会话版本。本包不读写任何 HTTP;路由、cookie 与强制点由后续账户包承接。

密码哈希使用 node 的 scrypt,参数固化为一组(N=16384、r=8、p=1、32 字节盐、64 字节密钥)。存储编码内嵌其参数(`scrypt$N$r$p$<salt>$<hash>`),校验按编码内的代价重算,未来的代价升级可逐行迁移哈希。校验以恒时比较器比对派生密钥,对本模块未曾产出的任何值一律返回 false 而不抛错。

## 存储契约

一个 store 持有一个 SQLite 数据库文件,默认位于 harness home 内的 `qilin-accounts/accounts.db`(`QILIN_HOME`,回退 `~/.dsh`),也可注入路径或 `:memory:`。构造器创建父目录、打开数据库并执行幂等 DDL:users 的 email 唯一索引与非空 OAuth 身份的部分唯一索引均以 `CREATE ... IF NOT EXISTS` 建立。模式版本存于 `user_version` pragma;新建库在建表后写入版本号,来自更新构建的数据库会被拒绝而非静默服务。唯一性冲突以 `AccountConflictError` 呈现并携带 `email` 或 `oauth` 类别;每次读取都会校验解码的持久行,被手工改坏的角色或标记列会大声失败,而不是流入 RBAC。

## 组合方式

本包是共享域库,不是 Cordis 插件;消费方直接构造 `SqliteAccountStore`。其 invariant 伴生插件有意为空:它拥有的每个持久关系(唯一 email、唯一 OAuth 身份、会话归属)都由模式约束强制并在每次读取时重新校验,不存在可供伴生观察的跨插件关系。

## 模型体验

无,因为本包的账户与会话记录是服务端持久状态,绝不会进入模型请求、提示词或工具结果。

#### KV Cache 影响

无;本包不产生任何模型可见内容,因此不存在前缀、增长或失效行为。

## 已知限制与顺延工作

- **尚无模式迁移路径** —— 存储拒绝来自更新构建的数据库,且未来加列所需的迁移步骤尚不存在;首次模式变更必须引入其一。
- **OAuth 列仅作存储预留** —— 联结列及其部分唯一索引已就位;尚无任何 provider 流程读写它们。
- **email 唯一性按原文精确比较** —— 不做大小写折叠或归一化;是否归一属产品决策,待真实流程需要时再定。
- **到期语义跟随墙钟** —— `expiresAt` 为绝对 epoch 毫秒,时钟回拨会让会话提前过期而非延长。
